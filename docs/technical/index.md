# Technical Reference

This section is for practitioners who need implementation-specific guidance.

For a public proof of concept, keep this section intentionally high level. Detailed internal documentation can be introduced after the site is hosted in an approved internal environment.

## Appropriate content

- repository conventions
- contribution workflow
- framework architecture
- general development patterns
- links to approved internal docs

## Avoid in public repositories

- internal server addresses
- credentials
- network paths
- environment-specific security configuration
- restricted system topology
