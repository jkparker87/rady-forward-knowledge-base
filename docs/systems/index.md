# Systems & Data Flows

This section explains the **role of major platforms**, when they should be used, and how they connect conceptually.

It is intentionally not a replacement for:

- detailed data catalog metadata
- source-code repositories
- infrastructure diagrams containing restricted information
- environment configuration
- credentials or connection instructions

## Recommended system-page structure

Each system page should answer:

1. What problem does this platform solve?
2. Who uses it?
3. What kinds of data or work belong there?
4. What are its upstream and downstream relationships?
5. What does **not** belong there?
6. Where is the authoritative technical documentation?
